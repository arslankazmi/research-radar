01What it does

Every "arXiv digest" tool is a one-way email, arXiv-only, ranked against a profile you set once. Running inside OpenClaw — an always-on, multi-channel assistant — lets the radar do what an inbox can't.

💬

It's a conversation

The digest lands as a numbered thread you interrogate: summarize #3, why #5, more like #2, mute KV-cache.

🛰️

It's multi-source

Papers and model releases and trending repos and curated researcher blogs — one adapter per source, RSS-preferred with a scrape fallback.

🧠

It learns

Your 👍/👎 become few-shot exemplars that re-tune the relevance judge over time. Quality is measurable — it ships a precision@k self-eval.

🛡️

It never falls over

Per-source failure isolation: one dead feed never sinks the digest. No model/key? A keyword scorer still produces one.

03One request, end to end

What actually happens on /radar (field and file names are the real ones):

  1. buildAdapters(config.sources)

    The registry instantiates one SourceAdapter per configured source (arXiv cs.LG/CL/CV, HF trending, GitHub ML, Hacker News, the RSS/scrape researcher feeds).

  2. fetchAll() — parallel

    Promise.allSettled runs every adapter at once; a rejected source logs a warning and contributes []. Each returns normalized Item[] with a stableId from the canonical URL.

  3. dedupe(items)

    Collapses exact-id duplicates, then near-duplicate titles (token Jaccard ≥ 0.9), keeping the richer summary.

  4. scoreItems(items, profile, { llm })

    One batched prompt — interest text + 👍/👎 few-shot exemplars + numbered candidates → strict JSON [{id, score, reason}] from the agent's configured model. Muted topics forced to 0. On any failure: keyword fallback, scorer:"keyword".

  5. compose(scored, profile)

    Threshold by minScore, sort by score, take topN, group by sourceType → renderMarkdown (the numbered #N list) + a Canvas card object.

  6. deliver → react → applyReaction

    The digest posts to your channel. A 👍/👎/mute reply hits the message_received hook, appends an exemplar (or muted topic) to the profile, and the next run ranks a little more like you.

04Decisions & war stories

Pure core + thin entry + type shim

All logic depends only on ports we own; one thin file touches the SDK.

Why: @openclaw/plugin-sdk is private:true — not on npm; clawhub bundles it at publish. A naïve all-SDK plugin can't even compile locally. The shim (src/plugin/sdk.d.ts) satisfies tsc without it.

Cron with a fallback

Attempt native scheduleSessionTurn; otherwise instruct the agent to schedule via the built-in cron tool.

Why: scheduleSessionTurn is bundled-only and absent for external plugins — discovered by reading the SDK runtime types, not the happy-path docs.

RSS-preferred, scrape fallback

Feedless sites route through a scrape adapter.

Why: the "obvious" feeds don't exist — gwern.net and Anthropic publish no RSS, and Karpathy moved to Bearblog. Guessed URLs would have silently returned nothing.

LLM-as-judge ⟂ keyword fallback

The judge degrades to keyword overlap, never to an empty digest.

Why: availability > peak quality for a daily habit. A missing key or a garbled JSON response should still ship something useful.

precision@k self-eval

runGoldenEval scores the ranker against a labeled set.

Why: a ranker you can't measure is a vibe. It also exposes the recall blind spot — misses hide upstream of the judge, at the fetch stage.

Dependency-injected everything

HttpClient, Llm, KvStore, Logger are ports.

Why: the whole pipeline runs offline against fixtures — 121 tests and a --dry-run with no network, no key, no OpenClaw runtime.

07Quickstart

Try the pipeline locally (no OpenClaw, no key)

bash
git clone https://github.com/arslankazmi/research-radar.git
cd research-radar && npm install
npm test                       # 121 tests
npm run dry-run -- --offline   # render a digest from fixtures

Install into a deployed OpenClaw instance

bash
npm install                              # OpenClaw never installs plugin deps
openclaw plugins install --link "$(pwd)" # TS entry runs via jiti — no build
openclaw gateway restart
openclaw plugins inspect research-radar --runtime --json

Then allow the optional tools with {"tools":{"allow":["research-radar"]}} in ~/.openclaw/openclaw.json. Full walkthrough: docs/LOCAL_TESTING.md.
